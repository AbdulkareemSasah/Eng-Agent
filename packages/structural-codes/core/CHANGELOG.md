# Changelog

## Unreleased

- Package skeleton: `pyproject.toml`, gate configuration, `__version__` (B-255).
- Errors, check metadata and the check_id rule: `structural_codes.errors`, `structural_codes.meta` (B-256).
- Check inputs, `bounded` and `unbounded` helpers, `ratio_limit` and preconditions: `structural_codes.inputs`, `structural_codes.applicability` (B-257).
- Trace recorder: `structural_codes.trace.TraceRecorder` (B-258).
- Verdict builder `TraceRecorder.verdict` and governing selection `structural_codes._verdict` (B-259).
- Check decorator, packs and registry: `structural_codes.check`, `structural_codes.pack`, `synthbase` test fixture pack (B-260).
- Content hash over the static import closure (pack, `structural_codes`, `eng_contract`), dynamic-import rejection and `lint_scope_violations`: `structural_codes.content_hash`, `structural_codes._closure`, `hashpack` test fixture pack (B-261). The dynamic-import rule applies to the check's pack modules only; `structural_codes` and `eng_contract` sources are hashed but exempt, so every real pack (which builds `PACK` with `structural_codes.pack`) can be hashed.
- Runner: `structural_codes.evaluate`, `evaluate_batch`, `BatchItem`, `Evaluation` and `Mode` (module `_runner`): validation through `validate_input`, member scope, preconditions, declared gaps, `ERROR` isolation per item, governing verdicts and the `verdicts.set/1` payload (B-262). Until the lifecycle task every check is a `draft` and `production` mode is refused. In a batch, the `field` of an item error is `items[<k>].<field>`, the contract field-path form. A `ValueError` is contained as an `ERROR` verdict only when it is a math-domain error (the message forms of the math module); any other `ValueError` propagates as a defect of the check.
- Overlay mechanism: `structural_codes.overlay` (`Overlay`, `Inherited`, `Overridden`, `Added`, `Removed`, `InheritedCheck`): completeness, clause-map rules, derived inherited checks whose content hash includes the base check's hash, removed checks answering `NOT_FOUND` with the reason; `Pack` validates `base`/`overlay` and `Registry.of` resolves overlay packs (an overlay of an overlay is refused); `synthover` test fixture pack (B-264).
- Verification: case-file models, `compare`, `verify_check`, `verify_pack` and the report of the unmet conditions of spec 4.9.4 (`structural_codes.verification`), and the safe YAML loader that rejects duplicate keys (`_yaml`) (B-263). Additions to spec 4.9.1 for the owner queue: an optional `covers` list on `boundary` cases and `<id>: <test>` entries in `review.boundary_tests` tie boundary evidence to a precondition or gap id; `program_comparison.not_available` together with program-comparison cases is refused.
- Lifecycle: `structural_codes.lifecycle` (`State`, `ApprovalsFile`, `Approval`, `Withdrawal`, `resolve_state`): the `approvals.yaml` model with AC23 validation (kind must fit inherited and non-inherited checks), the runtime state from approvals and content hash only (`withdrawn`, `approved`, `draft`; never `verified`), and mode usability in the runner replacing the T8 default: `production` needs `approved`, a `withdrawn` check is refused in both modes (B-265). A pack whose `approvals.yaml` is absent has no approval (every check is `draft`, a warning is logged); an invalid file raises `ApprovalsFileError`.
- Public API declared early: `public_modules` lists the spec 0001 section 4.1 modules that exist, so the packs can import them; T14 adds `lifecycle` and `notes` (B-382).
- Calculation-note renderer: `structural_codes.notes.render_html` (self-contained HTML, English with proposed Arabic labels, `DRAFT` watermark, `html.escape` on every value) and the label table `_labels` (B-267). Arabic wording is the spec 4.10 proposal (Q7); table headers without a spec Arabic term are English only. A trace whose check is not in the registry raises `NOT_FOUND`. `notes` is declared public by T14.
