# Changelog

## Unreleased

- Package skeleton: `pyproject.toml`, gate configuration, version constants `CONTRACT_VERSION`, `UNITS_VERSION`,
  `__version__` (B-010).
- Error codes, retry rules, warnings and `ContractError` (`errors`, internal `_types`), spec 4.2.3 and 4.2.4 (B-011).
- Canonical JSON (RFC 8785): `canonical_json`, `loads`, `payload_sha256`, `CanonicalJsonError`, spec 4.3.1 (B-012).
- ULID identifiers, `Timestamp`, clocks and id sources (`ids`, internal `_ulid`), spec 4.3.2 (B-013).
- Units of canonical/1: exact cited factors, `convert`, `convert_exact`, quantity kinds, field suffixes and the CSI unit systems (`Ton_*` raise `UnitGapError`, gap G-1), spec 4.7 (B-014). Factor citations unconfirmed (gap G-4, `docs/verification/units.md`).
- `Quantity`, `LabeledQuantity` (no arithmetic, physical equality, same-dimension ordering, consistent hash) and `Cited`, spec 4.8 (B-015). A float enters the exact comparison as its shortest round-trip decimal so that AC35 holds (owner queue).
- Build: the package declares its own test dependencies (pytest, Hypothesis) in `[dependency-groups] dev`, so it keeps them when it leaves the workspace and the gate's imports rule IM006 finds them declared; its tool configuration uses only keys of the gate's allowed set (eng-dev-gate spec 4.12): a `[tool.ruff]` table with `line-length`, `src` and the root's rule set in place of `extend`, no `[tool.mypy]` table (the root's applies, `warn_unreachable` included), pytest `addopts` without the coverage options and no `[tool.coverage.*]` tables, because the gate runs coverage itself with the thresholds of `[tool.eng-gate]` (B-093).
- Provenance, envelopes (`SuccessEnvelope`, `FailureEnvelope`, `Envelope`), `make_success`, `make_failure` and `ResultRecord`, spec 4.2.2, 4.2.5 and 4.4 (B-016). `RefInput` validates ref text with a local pattern until `refs` (T8) defines `RefString`.
- References (`refs`, internal `_pointer`): `Ref`, `RefString`, `LocalTraceRef`, `rebase_local_ref`, `parse_ref`, `JsonPointer` (RFC 6901 string form), `RefRule`, `RecordSource`, `resolve_ref` and `ResolvedRef`, spec 4.6 (B-017). Additive details for the owner queue: `RefRule` and `parse_ref` take an optional `field` so errors carry it; `resolve_ref` takes an optional `ids` for the incident id of the `INTERNAL` case; `RecordSource` also has `payload()` for split payloads.
- Input-parameter metadata and validation (`params`, internal `_validation`): `eng_param`, `ParamSpec`, `ParamModel`, `InputPolicy`, `validate_input`, `ValidatedInput`, `ContractDefinitionError`, spec 3.6 and 5 (B-018). Additive details for the owner queue: quantity literals are `Quantity`-typed fields (the field type is the literal type; `Ref` is added by `ref_capable`); shape is checked as strict JSON; every suffixed field name needs its unit, with or without `eng_param`.
- Verdicts, model issues and calculation traces (`verdicts`, `issues`, `trace`): `Verdict`, `Subject`, `ModelIssue`, `CheckModelSummary`, `Trace` and its parts, spec 4.9 (B-019). Additive details for the owner queue: an unknown unit in a `TraceInput` or `TraceStep` raises `UnitError` (as `Cited` does) rather than `ValidationError`; `TraceStep.formula` and `source` are required; `outputs` may not name constants; a host verdict may also carry a `trace_ref`.
- Fix: `params` no longer imports `pydantic_core` (the gate's imports rule IM006: eng-contract declares only `pydantic`); `eng_param` takes pydantic's `...` as its required-field default, which pydantic turns into the same sentinel. The `type: ignore` in `test_params.py` carries its issue reference, and `.gate/ratchet.json` records the package's one `type_ignore` (B-087).
- Kind names, `KindRegistry`, `NEUTRAL_KINDS`, `KindNotRegistered` and the eight `model.*` kinds (`kinds`, `kinds.model`), spec 4.10.1 and 4.10.2 (B-020). `joints` of `model.area_placements/1` is an optional list without a length rule (spec silent; owner queue).
- The `forces.*` (`joint_reactions`, `member_end`, `story_drifts`), `basis.*` (`design_basis` with `DesignBasis.missing`, `engineer_input`), `verdicts.set/1` and `issues.model_check/1` kinds, spec 4.10.2 (B-021). Owner queue: the spec basis path pattern allows no capital letters, so a path ending in `_MPa`, `_kN` or `_kNm` cannot exist and the unit-suffix rule applies only to lower-case suffixes (`_mm`, `_ratio`, `_deg`, ...); `counts` of `verdicts.set/1` must hold one entry per status; no pointer helper is added (the spec names only `missing`).
- Workspace resolution and location probes (`store`: `Workspace`, `resolve_workspace`, `LocationClass`, `LocationProbe`, `FakeLocationProbe`, `default_location_probe`; internal `_workspace`, `_probe_posix`, `_probe_windows`), spec 4.5.1 and 4.5.2 (B-022). Windows probe rules run over a `WinApi` port with a fake on every OS; the `ctypes` port needs the Windows CI job and local checks (`docs/local-testing.md`). Owner queue: the Win32 constants are written from memory of the SDK headers and are proven only by AC15 on Windows; a workspace folder that cannot be created is `PRECONDITION_FAILED` (`local_workspace`); the package declares no `windows_tests` path yet (`pyproject.toml` is outside the T13 files).
- Result store and model state (`store`: `ResultStore`, `ModelStateStore`, `ModelState`, `StoreWriteError`, `StoreIntegrityError`; internal `_results`, `_model_state`, `_fs`), spec 4.4, 4.5.3 to 4.5.5 (B-023). Atomic exclusive writes with the 0.05, 0.1 and 0.2 s retries, payload split above 8 MiB, hash check on read. Owner queue: `get` verifies a split payload but returns the record with `payload` null (`payload()` loads it); `increment` replaces `fingerprint` and `file_sha256` (None clears them); `record_promotion` appends once and keeps the revision; `ModelStateStore` takes an optional `sleep`.
