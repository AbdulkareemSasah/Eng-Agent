# Local testing: eng-harness

No host program is involved. These checks need the owner's machine (plan 0001 section 4; completed by T16 and T19):
1. The overhead benchmark and the fsync cost on the owner's workstation disk, with antivirus active, against the 20 ms target.
2. The run lock is released after killing the engine from Task Manager (`uv run pytest tests/unit/test_journal_reader.py tests/windows/test_run_lock_windows.py -m windows`; the second file starts a holder process, kills it, and checks that the engine's lock refuses a second process while a run is under way; the Windows job runs only `tests/windows`, so also run `tests/replay/test_resume.py::test_resume_holds_the_run_lock` there: the same for `Engine.resume`).
3. A resume after a forced power-off of a virtual machine (power loss is not covered by tests).
4. File-copy promotion onto a folder the engineer uses, including a target file open in another program.
5. Plan 0001 T11b (spec 0001 AC31, AC32) against a real host and adapter, once spec 0002's `ToolPort` adapters exist: kill the host program during a write and resume (the adapter's `reconcile` for each outcome `applied`, `not_applied`, `partial` and `unknown`, and a tool without a reconciler), the engineer's answer to the `engine.in_flight` request, the adapter's `read_back` for a write found applied (its result, and a failure while the host is busy), and a read killed in flight. Only the fakes have run these.
6. Plan 0001 T11c (spec 0001 AC34, AC63, AC64) against a real host and adapter, once spec 0002's `HostPort` exists: close the host and reopen the model's last saved file in a new instance (`locate`, units read against the new instance, the comparison with the last save, a model reopened with writes after that save); kill the host program and resume (`model_not_loaded`, `restore` and the instance `HostPort.restore` returns, `host_started`, units read against it before the first live step); `accept` of an engineer's change to the model. Only the fakes have run these.

2. A second server (`long` role) attaching by pid to a server-launched instance.
3. The live `tools/list` fingerprint against the allowlist's, and that the real `csi_status` reports `read_only` and `script_enabled` false (the build check requires both).
4. The `serverInfo` the Sasaah server reports.
5. Every table key and reply field of spec 0002 sections 4.6.2 and 4.6.4, and the reply fields of every mapped list tool.
5b. Plan 0002 T12b (spec 0002 AC24, OQ-G10), the read-back of `check_model` against real ETABS: the `READBACK` columns in `products/_etabs.py` (`UniqueName` and `Section` of `Area Assignments - Section Properties`, `Name` and `Thickness` of `Wall Property Definitions - Specified`), that the table's thickness is in the present units (the helper converts it to mm with the model's length unit), and the AC24 read-back itself, including a thickness written in the wrong units reading back x1000, a changed section and an engineer's edit behind the harness. Only the synthetic fake has run it.
5c. Plan 0002 T13 (spec 0002 AC28, OQ-G10), the reply fields the analysis, design and results mappers assume, against real ETABS: the `{items, truncated}` envelope of the `csi_results_*` tools; reaction rows `joint`, `case`, `kind`, `step`, `F1` to `M3`; frame-force rows `frame`, `case`, `kind`, `step`, `end`, `station`, `P`, `V2`, `V3`, `T`, `M2`, `M3`, and that `end` is spelled lower case `i` or `j` (any other value is stored as no end, so `I` or `J` would lose the marker); drift rows `story`, `case`, `direction`, `drift`, `label`, `x`, `y`, `z`; the status reply `{cases: [{case, status_code}]}`; the rows of a design result of each kind; and the `Analysis Messages` table key and its columns (`ANALYSIS_MESSAGES` in `products/_etabs.py`). Only the fake has run it.
5d. Plan 0007 T5 (spec 0007 AC31, OQ-G10), against real ETABS: that `csi_list_frame_sections`, `csi_list_area_sections`, `csi_list_materials`, `csi_list_load_patterns` and `csi_list_load_combos` reply `items` with a `name` each (the name lists), the `Analysis Messages` table key and columns, that a saved `.EDB` copied by the adapter is a file ETABS opens with the same hash as the working file, and that `csi_open_model` on a new path replaces the open model without saving it. Only the fake has run these.
6. A server `timeout` during a write and during an analysis, the units afterwards, each reconciliation rule, `locked` after a completed analysis, and a proof-of-end mechanism for an abandoned analysis call; after a `timeout` on a role, re-attachment with `launched: false`, `csi_exit` refused, and what `csi_status` reports.
7. Fingerprint stability and the blind spots of the read set.
8. `close_started` closing a hidden launched instance and leaving a visible one.
9. The host-instance lock across two engine processes.
10. `dxf-prep/prepare` and `etabs-model/build` through the adapter, including the configuration rewrite and the build-artifact hash.
11. `eng-harness doctor` on the owner's machine, including the integrity level and installed products.
12. Record mode on a copy, and the owner's review of the recordings before commit.
13. `uv run pytest tests/windows` on the owner's machine, with the antivirus and endpoint tools it runs: Job Object nesting under the engineer's terminal or scheduler, and the breakaway case with a real server and host program (none of the tests in `tests/windows` that start real processes has ever run on Windows: the container CI is Linux only and runs only the fake-based ones; the owner runs the whole folder, `uv run pytest tests/windows -m windows`, including the breakaway case (a host program started by a server survives the server's job) and the engine-kill case (every member of a server's job ends when the engine is killed), before relying on the launcher). Also on a shared machine with another user's host program running: `WindowsProcessInspector.snapshot` and `children` leave it out and log its pid, while `identity` on its pid raises (B-389; the rule itself runs against the fake kernel32 in CI).
14. `ProcessTransport` and `ServerManager` over the Windows launcher with the real Sasaah server: the MCP handshake on the launcher's pipes (raw handle-backed files, read and written by worker threads), a complete uncached `tools/list`, a call that outlasts the client backstop, a server killed during a call (read and write codes, restart, re-attach by pid), and a shutdown that ends the server on end-of-file of its standard input without ending a running host program (only the Linux fakes have run it).
