# ADR-0003: httpx2 as a direct runtime dependency of eng-harness (the shared HTTP client of the provider layer)

Status: Proposed · Date: 2026-11-04 · Deciders: owner

## Context
Both provider adapters ([spec 0009](../specs/0009-providers.md) §4.5) must send their requests through one client that
we configure: redirects off (a key must not follow a redirect), no automatic retry, a bearer authentication hook that
holds the key as a secret value, and an injectable transport so tests replay recorded exchanges without the network.
The OpenAI-compatible SDK inside PydanticAI accepts such a client. Process/04 §7 requires an ADR for a runtime
dependency.

Measured on 2026-11-04 in a scratch uv project outside the repository (CPython 3.14.6, Linux): in the resolved set,
`pydantic-ai-slim` 2.65.0 (`httpx2>=2.7`) and `openai` 3.45.0 (`httpx2>=2.12.0,<3`) both depend on `httpx2` 2.16.0,
and `httpx` 0.28.1 was in the set only because the probe project asked for it. `httpx2` has `AsyncClient` with
`follow_redirects`, `trust_env` and `transport` parameters, and `MockTransport`. Sizes are installed files from each
package's `RECORD`; licenses are as published in metadata, to be verified by the gate's license check; maintenance
health is for the owner to confirm at review.

## Decision
Declare `httpx2` as a direct runtime dependency of `packages/eng-harness`, pinned exactly in `uv.lock`, imported only by
`providers/_http.py` and `providers/_jev_format.py` (spec AC45). It is already in the lock through `pydantic-ai-slim`
and `openai`; declaring it avoids relying on a transitive dependency for code we write.

Rule for the implementing task: the library to declare is whichever one the pinned `pydantic-ai-slim` and `openai`
resolve to, so the lock holds one HTTP stack. If `uv lock` shows that has changed, this ADR is amended in the same pull
request before the dependency is added.

| Package (resolved version) | Role | License | Installed size |
|---|---|---|---|
| `httpx2` 2.16.0 | HTTP client, mock transport | BSD-3-Clause | 403 KiB |
| `httpcore2` 2.16.0 | Transport of `httpx2` (pinned to the same version) | to be checked by the gate | not measured |
| `anyio`, `idna`, `truststore`, `typing-extensions` | Dependencies of `httpx2` | to be checked by the gate | not measured |

## Consequences
- Easier: one client for both adapters with the security settings in one place; recorded-exchange tests with
  `MockTransport` need no extra development dependency.
- Harder: the project depends on a client library that a PydanticAI release may change; the exact pin and the adapter
  tests catch that at the upgrade pull request.
- If spike S-07 chooses a hand-written client for the TypeSafe API, it uses this library (spec 0009 §4.6).

## Alternatives considered
- **`httpx`**: not what the pinned PydanticAI and `openai` use, so it would put two HTTP stacks in the lock, and the SDK
  is given a client of the library it uses.
- **Standard-library `urllib`**: no asynchronous client, no cancellation of a request in flight, and no mock transport.
- **`aiohttp`**: not on the dependency path of the SDK we use; another stack to review.
- **Relying on the transitive dependency without declaring it**: breaks silently when a release drops it.

## Pre-mortem
A PydanticAI upgrade moves to another HTTP library and our client no longer fits the SDK's `http_client` parameter, so
the adapter stops using our redirect, retry and key settings. Early warning: the key-placement and no-redirect tests
(spec AC9, AC11) fail at the upgrade pull request, before it merges.
