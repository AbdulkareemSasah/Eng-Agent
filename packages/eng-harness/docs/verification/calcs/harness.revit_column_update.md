# harness.revit_column_update

- Calc id, version and content hash: `harness.revit_column_update` v1; the hash is the entry in `src/eng_harness/calcs/calcs.lock.json`
- Status: draft (bootstrap mode, ADR-0028 section 4; owner approval awaited, spec 0013 CW-G12)
- Method source: spec 0013 section 4.4.5, rules U1 to U10, as amended by B-610 (Q15 to Q17 decided: explicit `role_statuses` input, Revit `revit_placements` input, read-back identities, completeness, ordering, permutation comparison) and B-614 (U2 `reference` gate with missing roles as `unmapped`, no `expected_instances` on the plan, each `orientation` row is the `ORIENTATION_UNVERIFIED` issue of severity `info`). Input: `map` (`harness.frame_element_map/1`), `frames` and `sections` (this run's ETABS reads), `revit` (`harness.revit_structure/1`), inline `role_statuses` (`{family: {role: status}}`), `revit_placements` (the Revit `model.frame_placements/1` read used by R4), `changed` (the `#/changed` list of `harness.column_design_record/1`), and `compare.length_mm`. U1: targets per pair from the frame's ETABS section as references `<sections result>#/frame_sections/<i>/shape/<field>` (`rectangular` sets `section_b`/`section_h`, `circular` sets `section_D`; `other` is `not_updatable` `SHAPE_NOT_SUPPORTED` before U2). U2: the pair proceeds only if every required role for the element's family is `reference`, else `SECTION_ROLES_UNMAPPED`. U3: the element's current type with every role within `compare.length_mm` (exact `Fraction`, inclusive) is `no_change`. U4: the one same-family type within tolerance is `assign`; several are `TYPE_AMBIGUOUS`; none plans one new type per (family, ETABS section name) named after the section verbatim, duplicated from the current type of the first pair by `unique_id` (`NAME_CONFLICT` when taken). U5: a non-square rectangular target of a pair that proceeds to a write carries an `orientation` row with the ETABS rotation reference by `frame_id` first and the Revit rotation reference by `unique_id` second (actual input row indices; never compared, never written); blocked and `no_change` pairs carry none (lead decision). U6: each assignment carries `changed_in_design` when its frame is in `changed`, else `preexisting`; a new type lists one origin per pair in ascending `unique_id` order. U7: `expected.elements` holds one row per assignment (`type_id` for reuse, `family` and `type_name` for a new type), `expected.types` one row per new type with its U1 role references. U8: `complete` is true exactly when all referenced input records are complete. U9: `assignments`, `no_change` and `expected.elements` by `unique_id`; `not_updatable` and `orientation` by `frame_id`; `new_types` and `expected.types` by (family, ETABS section name). Ids in `assignments`, `no_change` and `expected` are `str(int)`; every length is a reference, never a number. The calc holds no engineering constant. A map pair whose frame, section, element, current type or Revit placement row the inputs lack is `INVALID_ARGUMENT`.
- Golden cases (`tests/data/golden/column_design/`; each derived by hand in its `derivation` field, synthetic data):
  - `revit-update-no-change.json` (§4.4.5 U3): current type 400 x 400 mm within 5 mm of a 400 x 400 mm target (decoy section at index 0 proves the lookup is by row). Result: one `no_change` row, nothing else.
  - `revit-update-reuse-type.json` (§4.4.5 U4): current type outside on `h`; one same-family type within. Result: one reuse assignment with `preexisting` origin and one element expectation.
  - `revit-update-new-type-shared.json` (§4.4.5 U4): two pairs of one family and section, current type outside. Result: one new type named after the section shared by two assignments ordered by `unique_id`, origins retained per pair.
  - `revit-update-name-conflict.json` (§4.4.5 U4): no type within, and the section name is taken in the family. Result: `not_updatable` `NAME_CONFLICT`, no new type, no assignment.
  - `revit-update-roles-unmapped.json` (§4.4.5 U2): an `unmapped`, a `candidate` and a missing required role, although every current type matches exactly. Result: three `SECTION_ROLES_UNMAPPED` rows ordered by `frame_id` (U2 runs before U3).
  - `revit-update-shapes.json` (§4.4.5 U1): circular target with an outside current type, and an `other` shape with reference roles. Result: one circular new type with a `section_D` role set, and `SHAPE_NOT_SUPPORTED` for the `other` pair (U1 runs before U2).
  - `revit-update-orientation-unverified.json` (§4.4.5 U5): a 400 x 600 mm reuse pair and a square reuse pair, with decoy ETABS and Revit rows at index 0. Result: one `orientation` row for the non-square pair with both rotation references at the actual indices; the square pair has none.
  - `revit-update-origin.json` (§4.4.5 U6): two new types with `changed` holding one frame. Result: `changed_in_design` and `preexisting` assignments, new types ordered by (family, section name).
