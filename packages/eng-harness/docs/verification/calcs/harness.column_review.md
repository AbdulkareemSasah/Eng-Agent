# harness.column_review

- Calc id, version and content hash: `harness.column_review` v1; the hash is the entry in `src/eng_harness/calcs/calcs.lock.json`
- Status: draft (bootstrap mode, ADR-0028 section 4; owner approval awaited, spec 0013 CW-G12)
- Method source: spec 0013 section 4.4.3 (rules R1 to R4); spec 0003 section 4.9 (rules S2 and S5) and section 4.4 (`report.top_n`). Inputs: `selection` (`harness.column_selection/1`), `host` (`harness.host_design_verdicts/1`), the three optional code-check `verdicts.set/1` inputs (`max_axial_strength`, `axial_flexure_uniaxial`, `longitudinal_reinforcement_limits`), `items` (`harness.column_check_items/1`), optional `previous` (`harness.column_review/1`), and `basis` (`basis.design_basis/1`, reading `report.top_n`). R1: only verdicts whose subject is `(frame, id)` in `selection.columns` are read; host verdicts require `source="host"` and each code-check input requires `source="code_pack"` with its matching check id. R2: members are aggregated per `(frame_id, source, check_id)` with worst status in S5 order (`FAIL > ERROR > NEEDS_ENGINEER > PASS > NOT_APPLICABLE`) and largest non-null ratio (or `None`); per column, `host_status` and `code_status` take the worst status of that source's members (or `NOT_APPLICABLE` when none), and `status` is `NEEDS_ENGINEER` when `not_checked` is non-empty or the column has no verdict, else the worst of its members. R3: `governing` per column is the first verdict of that column with a non-null ratio in S2 order (`<result_id>#/verdicts/<i>`), copying `ratio` without recomputing; `top` takes the first `report.top_n` selected verdicts in S2 order. R4: `changes` compares `members` against `previous.members` by `(frame_id, source, check_id)` using the S5 transition table (empty when `previous` is absent; ratio changes without a status change are not listed). Holds no numeric literal.
- Golden cases (`tests/data/golden/column_design/`; each derived by hand in its `derivation` field, synthetic data):
  - `column-review-sources.json` (§4.4.3 R1): R1 ignores unselected frame `B1`; concrete `C1` with code-pack checks only (`axial_flexure_uniaxial` 0.625, `longitudinal_reinforcement_limits` max(0.5, 0.25)=0.5, `max_axial_strength` 0.4) -> `host_status` `NOT_APPLICABLE`, `code_status` `PASS`; steel `C2` with host check only (0.55) -> `host_status` `PASS`, `code_status` `NOT_APPLICABLE`.
  - `column-review-two-ends.json` (§4.4.3 R2, R3): `C1` has `PASS` (0.6 at station 0) and `FAIL` (1.25 at station 3000) on `max_axial_strength` plus `longitudinal_reinforcement_limits` (0.5); member aggregates to `FAIL` with ratio 1.25; `governing` points to index 1; `report.top_n = 2` truncates `top` to 2 of 3.
  - `column-review-not-checked.json` (§4.4.3 R2, R3): `C1` has `PASS` (0.4) and `not_checked` `AXES_UNDECLARED` (gap `CW-G9`) -> `status` `NEEDS_ENGINEER` with `governing` 0.4; `C2` has `NEEDS_ENGINEER` without ratio -> `governing` `null` (0003 S2); `C3` has `SHAPE_NOT_CHECKED` and no verdicts -> `status` `NEEDS_ENGINEER`, `governing` `null`; all three in `attention`.
  - `column-review-changes.json` (§4.4.3 R4): compares against `previous.members` by `(frame_id, source, check_id)` showing `newly_failing` (`C1` `code_pack` `PASS->FAIL`), `newly_passing` (`C1` `host` `FAIL->PASS`), `other_changes` (`C2` `code_pack` `NEEDS_ENGINEER->PASS`), unchanged status with ratio change omitted (`C2` `longitudinal_reinforcement_limits`), `appeared` (`C3` `code_pack`), and `disappeared` (`C3` `host`).
- Property and contract tests: `tests/property/test_column_review.py` (`test_ratios_are_referenced_not_computed` checks every ratio in `governing`, `top`, `members` and `changes` against the input verdicts and previous members; `test_permutation_invariant` checks input order invariance); `tests/golden/column_design/test_golden.py` (registration, trace, `report.top_n` refusals, `meta.refs` and source/check-id refusals, `complete=False`, `HarnessCalcPort` integration); `tests/contract/test_column_design_kinds.py` (`ColumnReview` kind contract and S5 change rules).
- Reviewer and date: awaiting review
- Findings and open gaps: (1) Per 0003 §4.9 S2 ("verdicts without a ratio are ranked after all others and never count as governing"), a column whose verdicts all lack a ratio gets `governing: null`. (2) Per `_ReviewRow._needs_engineer_when_not_checked` in `kinds/column_design.py`, a non-empty `not_checked` requires column `status` to be `NEEDS_ENGINEER` even if another check failed (`host_status` and `code_status` retain the worst status per source, and `failing` / `attention` follow `status`). (3) `not_checked` and `gaps` on each column row are taken from `items.not_checked` (sorted unique codes and non-null gaps).
