# harness.column_select

- Calc id, version and content hash: `harness.column_select` v1; the hash is the entry in `src/eng_harness/calcs/calcs.lock.json`
- Status: draft (bootstrap mode, ADR-0028 section 4; owner approval awaited, spec 0013 CW-G12)
- Method source: spec 0013 section 4.4.1, rules L1 to L3; spec 0003 section 4.11 P2 for the exact squared plan distance. L1: the scope answer (the stored `ColumnScopeRequest` of spec 0013 section 4.3) names frames, or selects by stories and sections (a frame is in scope when its story is selected, when stories are given, and its section is selected, when sections are given); an unknown frame, story (no frame has it) or section (not a frame section) is an error issue, sorted by code and name, and a repeated name counts once. L2: a frame in scope is a column when `(xj - xi)^2 + (yj - yi)^2 <= compare.length_mm^2`, compared as exact `Fraction`s of the stored values (inclusive boundary); otherwise it is excluded `NOT_VERTICAL`. The contract frame `kind` is not read (spec 0013 C3). L3: per column the section, its shape (`rectangular`, `circular`, `other`) and material from `model.sections/1`, the story, and `length_mm`, the square root of the exact squared end distance as a display float. `status` is `FAIL` on an error issue or an empty selection, else `PASS`. Columns and exclusions are sorted by frame id, so the output does not depend on the order of any input list. The calc reads only `compare.length_mm` (missing, unconfirmed, not a number or negative: `INVALID_ARGUMENT`, no default; its unit is fixed by the path suffix, contract `DesignBasis`) and holds no constant and no numeric literal.
- Golden cases (`tests/data/golden/column_design/`; each derived by hand in its `derivation` field, synthetic data, integer coordinates so the exact comparison has no binary rounding):
  - `column-select-names.json` (§4.4.1 L1): scope by four frame names; three vertical frames with a rectangular, a circular and an `other` section (one given top end first), one horizontal beam excluded, one frame not named and not looked at. Result: pass.
  - `column-select-story-section.json` (§4.4.1 L1): story L2 and sections C40, W1 together; frames of another story, another section and no story are left out, a horizontal member in scope is excluded. Result: pass.
  - `column-select-vertical-boundary.json` (§4.4.1 L2): plan offsets (1, 2), (3, 4) and (-4, -3) against 5 mm, so d^2 = 5, 25 and 25 <= 25; lengths sqrt(9000005), sqrt(16000025), sqrt(12250025). Result: pass.
  - `column-select-not-vertical.json` (§4.4.1 L2): offsets (5, 1) and (4, 4), d^2 = 26 and 32 > 25, excluded (the second although each component is below 5 mm and its contract kind is `column`). Result: pass.
  - `column-select-unknown-names.json` (§4.4.1 L1): two unknown frame names beside a known column. Result: fail.
- Property test: `tests/property/test_column_select.py::test_permutation_invariant` (Hypothesis, derandomized; frames, frame sections and the scope lists permuted; body, content hash and trace equal)
- Boundary and contract tests: `tests/golden/column_design/test_golden.py` (registration and kinds, trace, each basis refusal with its field and message, tolerance zero, a fractional tolerance on both sides of a boundary, a selection with every frame excluded, unknown stories and sections, one filter alone, repeated names, the refusals below, scope shapes, a run through `HarnessCalcPort` with the scope as a field reference into `basis.engineer_input/1`)
- Reviewer and date: awaiting review
- Findings and open gaps: (1) Spec 0013 section 4.4.1 does not say what to do with a column whose frame has no story or whose section is not in `model.sections/1`; the kind requires a story, so both are refused with `INVALID_ARGUMENT` (`frames`, `sections`) as inputs the calc cannot use (spec 0003 section 4.2), and a frame that is excluded is never looked up. (2) A story is known when a frame of the read has it; the calc has no `model.stories/1` input (spec 0013 section 4.4.1 lists none). (3) Whether a CSI frame's ends give the verticality the engineer expects (offsets, cardinal points) needs the local test of spec 0013 section 12.
