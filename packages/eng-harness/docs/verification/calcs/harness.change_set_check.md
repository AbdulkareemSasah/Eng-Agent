# harness.change_set_check

- Calc id, version and content hash: `harness.change_set_check` v1; the hash is the entry in `src/eng_harness/calcs/calcs.lock.json`
- Status: draft (bootstrap mode, ADR-0028 section 4; owner approval awaited, spec 0007 EC-G4)
- Method source: spec 0007 section 4.4.1, rules K1 to K7, with the change-set model of section 4.3 (refused kinds and their gaps, section 4.3.2) and the bounds of section 4.8 (`bounds.thickness_min_mm` and `_max_mm`, `bounds.line_load_min_kN_m` and `_max_kN_m`, `bounds.area_load_min_kPa` and `_max_kPa`, `bounds.ratio_min_ratio` and `_max_ratio`; no default). Values are compared exactly (`Fraction`) in the canonical unit of their kind; a literal is converted with the factors of `eng_contract.units.unit` (no offset or pi for these kinds). An item id that contains `/`, is not 1 to 57 ASCII letters, digits, `_`, `.` or `-` (a page token of spec 0006 AC49 less the 7 of the field prefix), or is `revision` or `unlock` is the error `INVALID_ITEM_ID` (K3). Keys of K3 and K6 are the reported keys of spec 0003 section 4.7 D2, list name first. The read set's `sections` (`model.sections/1`) is optional (amendment B-543, AC39): a supplied one keeps its reference check, its area kinds and its completeness flag; without it no area kind is known, a `select` that names `area_kind` matches no area and is `EMPTY_SELECTION` with the detail "the selection of item <id> matches no area: the area kinds were not read (no model.sections/1)", and every other rule is unchanged (no new code, no guessed kind).
- Golden cases (`tests/data/golden/edit_cycle/`; each derived by hand in its `derivation` field, synthetic state and bounds):

  - `check-resolve-added-earlier.json` (K2, K4): a pattern, a wall section and a combination used by later items; basis and answer references. Result: pass.
  - `check-resolve-empty-selection.json` (K1): two empty selections. Result: pass.
  - `check-unknown-names.json` (K2): unknown frame, frame section, joint, material, pattern, area, combination, and a pattern added only later. Result: pass.
  - `check-duplicate-target.json` (K3): a section set twice through a selection; a combination set and deleted. Result: pass.
  - `check-bounds-unit-scale.json` (K4, baseline د6): 200 m is 200000 mm, out of bounds; 0.2 m is 200 mm, inside. Result: pass.
  - `check-bounds-edges.json` (K4): both bounds inclusive, values just outside, a conversion from N/m. Result: pass.
  - `check-source-missing.json` (K4): absent and unconfirmed basis fields, a basis field of the wrong kind. Result: pass.
  - `check-item-id-slash.json` (K3): ids `a/b`, `c/` and `/d` each give `INVALID_ITEM_ID` and are resolved as before; `ok-1` gives none. Result: pass.
  - `check-item-id-refused-kind.json` (K3, K5): a refused kind whose id has a slash gives `INVALID_ITEM_ID`, then `NOT_IMPLEMENTED`, and is not resolved. Result: pass.

- Reviewer and date: awaiting review
- Findings and open gaps: (1) the names of load cases are in no list (`harness.csi_name_lists/1` has none), so a combination term of type `load_case` is not checked by K2. (2) Known joints are the frame ends, area joints and restraint rows of the read set. (3) The `ref` of a resolved value points at the number itself (amendment B-544, AC40): `<basis>#/fields/<path>/value` for a basis value and `<answer>#/fields/change_set/value/items/<i>/<field>/value_<suffix>` for an input (`value_mm`, `value_kN_m`, `value_kPa`, `value_ratio`, which `ChangeSetDraft` fills and checks by `eng_contract.units`), so that step 8 passes it as a write argument; the golden cases hold the new forms, and `tests/unit/edit_cycle/test_change_set.py::test_value_refs_are_write_arguments` validates each against the CSI tool port's argument models. The calc stays version 1. (4) A basis value that is not a number is `SOURCE_MISSING`. (5) The workflow passes `BASIS_FIELDS` as the CalcPort `basis_fields`, as for the other calcs.
