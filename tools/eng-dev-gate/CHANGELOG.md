# Changelog

## Unreleased

- Package skeleton: `eng-gate` command shell with exit codes 0 to 3 and `--version` (B-030, plan task T1).
- Proposed ADR-0001 for the runtime dependencies (owner queue).
- Foundations A: finding and step results with text, JSON, Actions annotation and summary output, POSIX glob matching, GitHub event file reader and the temporary-repository test fixture (B-031, plan task T2a).
- Foundations B: `Git` port with subprocess adapter and workspace member discovery from `[tool.uv.workspace]` (B-057, plan task T2b).
- Configuration: root `.gate/gate.yml`, `GateConfig` and `[tool.eng-gate]` models, coverage and mutation floors (CF001, CF002, CF006 to CF008) and bootstrap mode read only from the gate root (B-032, plan task T3).
- Check orchestrator: `eng-gate check` with the step registry and the `lock`, `format`, `lint` and `types` steps (ST001), the `ToolRunner` port and its subprocess adapter (B-034, plan task T5).
- `agents render`, `agents keys` and `agents drift` with codes AG001 to AG007; the committed AGENTS.md files of the root and this package equal their rendering, so they are unchanged (B-033, plan task T4).
- `tests` step (`coverage run --branch` with pytest, line and branch compared separately, CV001 to CV003) and the `eng_dev_gate.pytest_plugin` pytest plugin (Hypothesis profile `ci`, deselection guard) (B-036, plan task T7).
- Base-commit gate: the global `--gate-root` option reads the policy and the mode from a checkout of the pull request's base commit while the head is the tree under check; provenance rule CF009 (gate root is not the base commit, running package outside it, head run with bootstrap off or when the base has the job's action) and AW09 for the first pull request of a job; `GateContext` is the reader that judging checks must use; the `agents drift` handler does not read it yet and is wired in a follow-up task (B-055, plan task T26).
- `forbidden` command and `check` step: the rule engine with scope and the policy file `.gate/forbidden.yml`, and rules FB001, FB002, FB003 and FB007 (FB000 for a file that does not parse); no inline waiver (B-039, plan task T10).
- CI part 1: the root workflow is thin and calls the composite actions `setup`, `gate`, `agents-drift` and `build` with the base-first steps (head checkout, base checkout into `.gate-base`, guarded base and head variants); the `gate` job runs `check --all` (any set of members) and the spike checks, the `windows` job stays on pushes to `build/v1`; new command `packages` (`--names`, `--json`) (B-035, plan task T6).
- `gate-check` part 1: front matter models, pull-request body parsing, plan and task lookup on the gate branch, file scope (renames count both paths; the `CHANGELOG.md` and `docs/local-testing.md` of a workspace member or of the plan's package are in scope beside a changed task file, AC10a) and diff budget (GC001 to GC009; B-042, plan task T13). `Plan-Task: none (...)`, the lane, base branch, protected paths and the job follow in T14.
- `licenses` step and command (allowed licenses of the dependency closure read from `importlib.metadata`, LC001 to LC003, exceptions from `.gate/gate.yml`) and the `docs-fresh` step (generated documents compared with their regeneration, GF001, GF002; AGENTS.md drift of the package) registered in `check` (B-048, plan task T19).
- Fix: in pull-request context the `tests` step runs each member's tests and coverage in an environment built from the judged tree and its lock file (`uv run --project <judged tree> --locked --all-packages --group dev`), with the base commit's pytest plugin (loaded by the new `judged_run.py` under its own module name) and the gate-generated coverage configuration; head runs are unchanged (B-059). A stale `uv.lock` in that run is ST001 of the `tests` step instead of an environment fault, and uv warnings are silenced with `--quiet` (review of PR 51).
- Fix: every `noqa` comment carries an issue reference and a reason, in a second comment after the directive (`# noqa: S603  # B-034: ...`; mypy rejects text directly after `type: ignore`, so the same form applies there), and the workspace guard of the AGENTS.md drift test is an assertion instead of a skip, so the ratchet step of T9 finds no RT006, RT002 or RT003 in this package (B-092).
- `forbidden` part 2: rules FB004 (I/O in block and rule modules), FB005 (numeric literals with the forms A1 to A3), FB006 (digits in a rationale) and FB008 (collection hooks that deselect tests) in `rules_b.py`; the engine reads the module globs of `[tool.eng-gate]`, and `.gate/forbidden.yml` gains `io_modules`, `cited` and `rationale`. The rules are registered in the step (`RULES = (*RULES_A, *RULES_B)` in `checks/forbidden/__init__.py`, a file added to T11 by the B-094 amendment). In `.gate/forbidden.yml` the key `rationale` is read into the field `rationale_policy` through a pydantic alias, because a model attribute named `rationale` would itself be an FB006 finding (B-040, plan task T11).
- `workflows` step and command: WF001 (actions pinned by commit SHA), WF002 (top-level permissions), WF003 (attacker-controlled expressions in `run:`), WF004 (`pull_request_target`) and WF005 (the exact jobs and base-first steps of `ci.yml`, judged by the base gate); WF000 for a file that does not parse. The step is registered last in `check`; the toy repositories of the existing `check` tests skip it because they have no `ci.yml` (B-050, plan task T21).
