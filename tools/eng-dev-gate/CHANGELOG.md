# Changelog

## 0.1.0

First version (tag `eng-dev-gate-v0.1.0` after the owner's approval; nothing is published to a package index). It
contains every entry listed below; README documents every command with an example (B-054, plan task T25, AC64).

## Unreleased

- `ToolRunner`: one tool call is bounded at 7200 s, the `limits.mutation_run_seconds` bound, in place of 900 s, because the harness test step outgrew 900 s in CI; a hung tool is still an environment fault, exit 3 (plan task T42, B-620; amendment B-619, owner request of 2026-11-26).
- `gate-check`: a changed path outside the task's globs that has a `tests/` directory segment, or is the `CHANGELOG.md` of a workspace member or of the plan's package folder, is a GC008 notice naming it a collateral edit; any other path outside the globs (also a `src/**/test_*.py` module) stays a GC008 error. `max_sessions` is an estimate that the gate never checks (B-566, plan task T41, AC10d, ADR-0036).
- `gate-check`: GC009 always reports counted lines, the task estimate and largest files as a notice; `max_changed_lines` has no cap and `limits.max_task_lines` is removed (B-553, plan task T40, AC11, AC13).

- `forbidden`: FB005 form A4 admits an integer literal given directly as the `version=` keyword of a callable named in `versioned.callables` of `.gate/forbidden.yml` (initially `calc` and `CheckMeta`). A version is an identity, so it carries no threshold (B-439, plan task T39, AC33a).
- Fix: the `mutation` step bounds `mutmut run` by the new `limits.mutation_run_seconds` (7200 s in the root `.gate/gate.yml`, owner queue), not by the 900 s bound of one tool call; a timeout is MU002 naming the limit; `ToolRunner.run` gains the keyword `timeout_seconds` and a timeout raises `ToolTimeoutError` (B-384, plan task T38, AC53c).
- Fix: the `mutation` step lists the member's other top-level files and folders (README, LICENSE, docs and so on) under mutmut's `also_copy`, so a mutated test run that builds the package or reads its own files behaves as in the tests step (B-371, plan task T37, AC53b).
- `gate-check`: an empty (0 bytes at head) `__init__.py`, added or modified, under a workspace member's `tests/` directory is in scope when another changed file in the same directory matches a task glob; a non-empty one, a renamed or deleted one, or one without such a neighbour stays GC008 (B-364, plan task T36, AC10c).
- Root `.gate/gate.yml`: `generated_globs` gains `**/docs/schema/**`, so JSON Schema snapshots no longer count toward the task diff budget (B-360, plan task T35, AC12c).
- `test-first`: for a package that the pull request adds, the base run blocks the package's import names (read from the head's `[tool.eng-gate] import_names`) with a meta-path finder of the base pytest plugin, so an editable install of the head cannot make a first-commit test pass at the base (TF004); the names are blocked before conftest.py files load (a conftest.py that imports one makes the base run red); a name that still resolves is TF011. `judged_run.py` gains the modes `pytest` and `probe` (B-357, plan task T34, AC27a).
- Fix: in pull-request context the `types` step runs the gate's own mypy with `--python-executable` set to the interpreter of the judged environment, and the `imports` step resolves IM006 with the judged environment's module map, so a dependency and its stub distribution added by the pull request no longer fail with `import-untyped` or IM006; `judged_metadata.py` now writes the interpreter, the distributions and the module map in one JSON object, which the `licenses` step reads as well; a stale `uv.lock` is ST001 of the step, a missing `uv` an environment fault; the `imports` step is a function of the whole step context; head runs are unchanged (B-347, plan task T32, AC54a).
- `risk-floor`: a `.gate/ratchet.json` change that gate-check accepts in the task's scope no longer raises the floor (the rise is AW05); any other change of it still does (B-348, plan task T33, AC21b).
- `gate-check`: a plan whose `spec:` is a directory (path ending in `/`) of clause specs loads every `*.md` directly in it from the gate ref with `git ls-tree` (GC005 for each that does not parse, GC004 when there is none); `covers` ids may carry a prefix (`BP-AC1`); GC016 lists the uncovered criteria of the clause specs whose prefix the plan covers and of the plan's own text; `.gate/gate.yml` `spec_globs` gains `**/docs/clauses/**/*.md`. New `Git.list_files` (B-344, plan task T31, AC12b, AC13a).
- Fix: a `mutation` run in which mutmut produced no mutant (a module-level lambda, decorated methods only) passes with the notice MU003 instead of MU002; mutants that no test covers count as survivors in the MU001 score, also when mutmut stops on them; MU002 stays reserved for a backend fault (B-339, AC53a, plan task T29).
- `risk-floor`: a `Plan-Task: none (<reason>)` pull request whose reason is not `spec and plan` records its risk from its one body `Risk:` line, RF004 without one (B-337, plan task T27, AC21a).
- Package skeleton: `eng-gate` command shell with exit codes 0 to 3 and `--version` (B-030, plan task T1).
- Proposed ADR-0001 for the runtime dependencies (owner queue).
- Foundations A: finding and step results with text, JSON, Actions annotation and summary output, POSIX glob matching, GitHub event file reader and the temporary-repository test fixture (B-031, plan task T2a).
- Foundations B: `Git` port with subprocess adapter and workspace member discovery from `[tool.uv.workspace]` (B-057, plan task T2b).
- Configuration: root `.gate/gate.yml`, `GateConfig` and `[tool.eng-gate]` models, coverage and mutation floors (CF001, CF002, CF006 to CF008) and bootstrap mode read only from the gate root (B-032, plan task T3).
- Check orchestrator: `eng-gate check` with the step registry and the `lock`, `format`, `lint` and `types` steps (ST001), the `ToolRunner` port and its subprocess adapter (B-034, plan task T5).
- `agents render`, `agents keys` and `agents drift` with codes AG001 to AG007; the committed AGENTS.md files of the root and this package equal their rendering, so they are unchanged (B-033, plan task T4).
- `tests` step (`coverage run --branch` with pytest, line and branch compared separately, CV001 to CV003) and the `eng_dev_gate.pytest_plugin` pytest plugin (Hypothesis profile `ci`, deselection guard) (B-036, plan task T7).
- Base-commit gate: the global `--gate-root` option reads the policy and the mode from a checkout of the pull request's base commit while the head is the tree under check; provenance rule CF009 (gate root is not the base commit, running package outside it, head run with bootstrap off or when the base has the job's action) and AW09 for the first pull request of a job; `GateContext` is the reader that judging checks must use; the `agents drift` handler does not read it yet and is wired in a follow-up task (B-055, plan task T26).

- CI part 1: the root workflow is thin and calls the composite actions `setup`, `gate`, `agents-drift` and `build` with the base-first steps (head checkout, base checkout into `.gate-base`, guarded base and head variants); the `gate` job runs `check --all` (any set of members) and the spike checks, the `windows` job stays on pushes to `build/v1`; new command `packages` (`--names`, `--json`) (B-035, plan task T6).

- Ratchet: `eng-gate ratchet [--update]` and the `ratchet` step of `check` count noqa, type-ignore, pragma, skip and xfail markers per package (RT001 to RT006, RT005 exits 2) and report a rise of `.gate/ratchet.json` against the gate root as AW05; `Clock` port for expiry dates (B-038, plan task T9).
- `gate-check` part 1: front matter models, pull-request body parsing, plan and task lookup on the gate branch, file scope (renames count both paths; the `CHANGELOG.md` and `docs/local-testing.md` of a workspace member or of the plan's package are in scope beside a changed task file, AC10a) and diff budget (GC001 to GC009; B-042, plan task T13). `Plan-Task: none (...)`, the lane, base branch, protected paths and the job follow in T14.
- `licenses` step and command (allowed licenses of the dependency closure read from `importlib.metadata`, LC001 to LC003, exceptions from `.gate/gate.yml`) and the `docs-fresh` step (generated documents compared with their regeneration, GF001, GF002; AGENTS.md drift of the package) registered in `check` (B-048, plan task T19).
- Fix: in pull-request context the `tests` step runs each member's tests and coverage in an environment built from the judged tree and its lock file (`uv run --project <judged tree> --locked --all-packages --group dev`), with the base commit's pytest plugin (loaded by the new `judged_run.py` under its own module name) and the gate-generated coverage configuration; head runs are unchanged (B-059). A stale `uv.lock` in that run is ST001 of the `tests` step instead of an environment fault, and uv warnings are silenced with `--quiet` (review of PR 51).

- Fix: every `noqa` comment carries an issue reference and a reason, in a second comment after the directive (`# noqa: S603  # B-034: ...`; mypy rejects text directly after `type: ignore`, so the same form applies there), and the workspace guard of the AGENTS.md drift test is an assertion instead of a skip, so the ratchet step of T9 finds no RT006, RT002 or RT003 in this package (B-092).
- `forbidden` part 2: rules FB004 (I/O in block and rule modules), FB005 (numeric literals with the forms A1 to A3), FB006 (digits in a rationale) and FB008 (collection hooks that deselect tests) in `rules_b.py`; the engine reads the module globs of `[tool.eng-gate]`, and `.gate/forbidden.yml` gains `io_modules`, `cited` and `rationale`. - `risk-floor` command and job (B-044, plan task T15): the floor is the union of the risks of the entries of `.gate/risk-map.yml` and of each member's own map matching a changed path, read at the base and the head commit; it must lie within the recorded risk (plan, changed spec and plan documents, or the `Risk:` line on a `lane/` branch). Codes RF001, RF002, RF004 and RF003 (invalid or missing map, exit 2); inputs `--event` or `--base --head --body-file`; composite action `risk-floor` and the `risk-floor` job in `ci.yml`.
- `mutation` step and command (`--package`, `--all`, `--base`): mutmut on the R1 and R2 modules changed against the merge base, MU001 below `mutation_min` (floor 80), MU002 where mutmut cannot run (Windows: notice locally, fault in CI); proposed ADR-0002 chooses mutmut; new runtime dependency mutmut (B-049, plan task T20).
